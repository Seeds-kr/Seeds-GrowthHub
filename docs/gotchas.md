# 함정 (Seeds GrowthHub)

이 레포에서 일하기 전에 읽는다. **한 번 당한 것만** 적는다 — 일반론이 아니라
실제로 시간을 잃은 지점이다.

## `seeds-preview/` 의 스크립트는 레포 사본이 아닐 수 있다

`seeds-backup.service` 는 레포의 `ops/backup.sh` 가 아니라
`/home/harvester/seeds-preview/backup.sh` 를 돌린다. 이게 **복사본**이라
한쪽만 고치면 갈라진다.

2026-08-19 실제로 갈라져 있었다. 배포본에는 8-15 에 추가된 업로드 파일 백업이
있었고 **레포본에는 없었다.** 레포만 보고 "백업이 DB 만 뜬다"고 판단하면 틀린다
— 방향이 반대였다.

**적용.**

- `ops/*.sh` 를 고쳤으면 `seeds-preview/` 쪽이 사본인지 링크인지 먼저 본다.
- 반대로 라이브 동작을 판단할 때 레포 사본만 읽지 않는다. 도는 것은 배포본이다.
- `backup.sh` 는 2026-08-19 에 레포를 가리키는 심볼릭 링크로 바꿔 단일 출처로
  만들었다(`preview.sh` 는 아직 사본이다).

## `node e2e/stories.mjs` 를 직접 돌리면 결과가 거짓말을 한다

진입점은 **`ops/verify.sh`** 다. 그게 두 가지를 세팅한다.

```
E2E_BASE_URL=https://seeds.harvester.kr      # 없으면 http://127.0.0.1:8088
E2E_ADMIN_EMAIL / _PASSWORD                  # ADMIN_EMAIL 에서 매핑. env 파일엔 없다
```

`~/.secrets/seeds-preview.env` 에는 `E2E_MENTOR_*`·`E2E_STUDENT_*` 만 있고
**`E2E_ADMIN_*` 은 없다.** 그래서 직접 돌리면 운영진 스토리 11개가 통째로
BLOCK 되고, 평문 `127.0.0.1` 로는 세션 쿠키가 안 실려 일부 학생 스토리가
401 로 떨어진다. **제품은 멀쩡한데 회귀처럼 보인다.**

2026-08-19 에 이걸로 세 번 헛짚었다. BLOCK 문구가 "계정 미설정 **또는** 로그인
실패" 라 로그인 실패 쪽으로만 읽었고, 그 앞에 속도 제한에 걸린 적이 있어서
그쪽이라고 지레짐작했다.

**적용.**

- 스토리를 돌릴 땐 `bash ops/verify.sh`. 직접 실행한 결과로 회귀를 판정하지 않는다.
- 로그인 제한은 **IP|이메일당 5분 10회**다. 손으로 검증 로그인을 섞은 직후에
  돌리면 진짜로 걸린다 — 둘을 구분하려면 창을 비우고 한 번만 돌린다.
