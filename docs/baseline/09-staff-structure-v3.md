# Seeds 운영진 구조 v3

## 1. 문서 목적

이 문서는 Seeds 운영진의 역할, 책임, 권한, 의사결정 구조, 멘토와의 협업 경계, 인수인계 구조를 정의한다.

이 문서는 GrowthHub의 하위 기능 명세가 아니라 Seeds 조직 운영 구조를 다루는 독립 문서다. 다만 GrowthHub는 이 운영진 구조가 실제로 작동하도록 돕는 시스템으로 연결된다.

## 2. 기본 관점

Seeds 운영진은 단순 행사 스태프가 아니라, Seeds의 운영 안정성, 학생 경험, 멘토와의 협업, 커뮤니티 지속성을 책임지는 조직이다.

운영진은 멘토를 관리하는 조직이 아니다. 멘토가 학생 성장을 돕는 데 필요한 운영 환경, 일정, 자료, 시스템, 커뮤니케이션을 지원하는 조직이다.

## 3. 운영진 구조의 목표

- Seeds 운영의 개인 의존도 감소
- 운영진 교체와 신규 유입 가능성 확보
- 멘토의 행정 부담 최소화
- 학생 성장 경험의 안정성 확보
- 회계, 모집, 행사, 시스템 관리의 책임 명확화
- 성장모델·커리큘럼·운영모델 정렬 결과를 실제 운영에 반영할 기반 확보

## 4. 운영진 구성 원칙

### 4.1 기능별 책임 구조

운영진은 “도와주는 사람들”이 아니라 기능별 책임을 가진 구조로 설계한다.

주요 기능:

- 전체 운영
- 모집/선발
- 정기모임/행사
- 회계/행정
- 시스템/데이터
- 학생 성장경험
- 커뮤니티/커뮤니케이션

### 4.2 멘토와 운영진의 경계

| 구분 | 멘토 | 운영진 |
|---|---|---|
| 핵심 역할 | 학생 성장 지원, 프로젝트 피드백 | 운영 프로세스 설계와 실행 |
| 주요 관심 | 팀과 학생의 성장 | 기수 전체 운영 안정성 |
| 개입 방식 | 조언, 피드백, 방향 제시 | 일정, 체크리스트, 안내, 지원 |
| 피해야 할 것 | 행정 업무 과부하 | 멘토링 내용 과도 개입 |
| 협업 접점 | 팀 상태 공유, 지원 요청 | 멘토링이 잘 되도록 환경 제공 |

## 5. 운영진 역할 상세

### 5.1 Program Lead

역할 목적:

- Seeds 전체 운영 방향과 주요 의사결정을 조율한다.

주요 책임:

- 연간/기수 운영 방향 정리
- 운영진 역할 조율
- 멘토와의 핵심 커뮤니케이션
- 주요 리스크 최종 판단
- 외부 협력 고위 조율
- GrowthHub 운영 원칙 관리

필요 역량:

- 전체 구조를 보는 능력
- 의사결정 능력
- 관계 조율 능력
- 멘토와 운영진 사이의 균형감

GrowthHub 사용 영역:

- 대시보드
- 회의록
- 리스크
- 운영 문서
- 권한/역할 현황

피해야 할 것:

- 모든 세부 업무를 직접 통제하는 것
- 멘토를 행정적으로 압박하는 것
- 역할별 책임을 모호하게 두는 것

### 5.2 Ops Manager

역할 목적:

- Seeds의 일상 운영, 회의, 작업, 일정, 행사 준비를 안정적으로 굴린다.

주요 책임:

- 운영진 회의 운영
- 회의록 관리
- 후속 액션 추적
- 운영 캘린더 관리
- 정기모임/행사 체크리스트 관리
- 행사 당일 운영 지원
- 작업 지연 리스크 확인

필요 역량:

- 실행력
- 꼼꼼함
- 일정 관리 능력
- 협업 도구 활용 능력

GrowthHub 사용 영역:

- Meetings
- Tasks
- Events/Sessions
- Documents & Templates
- Operations Dashboard

피해야 할 것:

- 운영 작업과 학생 프로젝트 이슈를 혼동하는 것
- 체크리스트를 형식적으로만 관리하는 것

### 5.3 Recruiting Lead

역할 목적:

- 신규 기수 모집과 선발 프로세스를 안정적으로 운영한다.

주요 책임:

- 모집 일정 수립
- 지원자 관리
- 평가자 배정
- 평가 진행률 관리
- 면접 일정 조율
- 합격/불합격 커뮤니케이션
- 모집 회고 정리

필요 역량:

- 프로세스 설계 능력
- 커뮤니케이션 능력
- 개인정보와 평가정보 관리 감각
- 공정성에 대한 감각

GrowthHub 사용 영역:

- Recruitment
- Evaluations
- Interviews
- Communication Logs
- Decision Logs

피해야 할 것:

- 평가정보를 불필요하게 공유하는 것
- 평가자 권한 범위를 넓게 두는 것
- 합격 결정의 근거를 기록하지 않는 것

### 5.4 Finance/Admin Lead

역할 목적:

- Seeds의 회계, 정산, 증빙, 행정 문서를 신뢰 가능하게 관리한다.

주요 책임:

- 수입/지출 기록
- 영수증 관리
- 정산 요청 검토
- 예산 항목 관리
- 월별/기수별 회계 요약
- 행정 문서 정리

필요 역량:

- 정확성
- 신뢰성
- 증빙 관리 능력
- 반복 업무 관리 능력

GrowthHub 사용 영역:

- Finance
- Attachments
- Documents
- Operations Dashboard

피해야 할 것:

- 회계 증빙을 개인 저장소에만 보관하는 것
- 승인/지급 상태를 기록하지 않는 것
- 회계 정보 접근권한을 과도하게 넓히는 것

### 5.5 Growth/Experience Lead

역할 목적:

- 학생 성장 경험, 프로젝트, 스터디, 회고, 멘토 피드백 흐름을 관리한다.

주요 책임:

- 학생 경험 여정 관리
- 프로젝트/스터디 운영 지원
- 회고 구조 설계
- 멘토 피드백 구조 관리
- 학생 참여 신호 확인
- 팀별 지원 필요사항 정리
- 성장모델·커리큘럼·운영모델 논의와 시스템 반영 연결

필요 역량:

- 교육적 관점
- 학생 관찰 능력
- 구조화 능력
- 성장모델과 운영현장의 연결 능력

GrowthHub 사용 영역:

- Projects
- Studies
- Feedback
- Reflections
- Activity Records
- Growth Dashboard

피해야 할 것:

- 성장증거를 성급히 평가점수로 해석하는 것
- 학생 회고를 감시 자료처럼 취급하는 것
- 멘토에게 긴 보고를 요구하는 것

### 5.6 System/Product Lead

역할 목적:

- GrowthHub 시스템의 구조, 사용성, 데이터 품질, 개선 우선순위를 관리한다.

주요 책임:

- GrowthHub 기능 요구사항 정리
- 운영진 사용성 피드백 수집
- 데이터 구조 관리
- 외부 도구 연동 방향 정리
- 개발 작업 큐 관리 지원
- 버그/개선사항 트래킹

필요 역량:

- 제품적 사고
- 데이터 구조 이해
- 개발자 또는 AI 개발 도구와의 커뮤니케이션 능력
- 운영 프로세스 이해

GrowthHub 사용 영역:

- Core
- System
- Integrations
- Audit Logs
- Data Model

피해야 할 것:

- 기능을 많이 만드는 것을 곧 좋은 시스템으로 착각하는 것
- 실제 운영진의 사용성을 무시하는 것
- 권한/가시성 문제를 나중으로 미루는 것

### 5.7 Community/Communication Lead

역할 목적:

- 학생 커뮤니티와 커뮤니케이션을 관리한다.

주요 책임:

- Discord 운영
- 공지 작성과 발송
- 학생 문의 대응
- 행사 참여 독려
- 커뮤니티 분위기 확인
- 알럼나이/졸업생 접점 지원
- 외부 홍보 콘텐츠 지원

필요 역량:

- 커뮤니케이션 감각
- 관계 형성 능력
- 커뮤니티 운영 감각
- 학생 눈높이에 맞춘 안내 능력

GrowthHub 사용 영역:

- Announcements
- Communication Logs
- People Directory
- Events
- External Links

피해야 할 것:

- Discord를 감시 도구처럼 운영하는 것
- 공지를 여러 채널에 흩어놓고 GrowthHub에 맥락을 남기지 않는 것

## 6. 의사결정 권한 구조

| 의사결정 영역 | 최종 판단 | 협의 필요 |
|---|---|---|
| 연간/기수 운영 방향 | Program Lead | 운영진, 멘토 필요 시 |
| 운영 일정 | Program Lead / Ops Manager | 관련 담당자 |
| 정기모임/행사 운영 | Ops Manager | Program Lead, Community 담당 |
| 예산 집행 | Finance/Admin Lead + Program Lead | 필요 시 운영진 |
| 모집 프로세스 | Recruiting Lead + Program Lead | 멘토/평가자 필요 시 |
| 멘토 배정 | Program Lead | Growth 담당, 멘토 |
| 프로젝트/스터디 운영 지원 | Growth/Experience Lead | 담당 멘토, Ops |
| 시스템 기능 우선순위 | System/Product Lead + Program Lead | 운영진 사용자 |
| 커리큘럼/성장모델 변경 | 별도 성장모델·운영모델 논의 | 멘토, 운영진, 필요 시 학생 의견 |
| 운영진 역할 조정 | Program Lead | 당사자, 관련 담당 |

## 7. Escalation 구조

### 7.1 학생/팀 이슈

```text
학생/팀 이슈 감지
→ 담당 멘토 확인
→ Growth/Experience Lead 공유
→ 필요 시 Program Lead 판단
→ 운영진 지원 또는 멘토와 공동 개입
```

### 7.2 운영 이슈

```text
운영 이슈 감지
→ 담당 운영진 확인
→ Ops Manager 공유
→ 필요 시 Program Lead 판단
→ 관련 담당자와 해결
```

### 7.3 멘토 관련 이슈

```text
멘토 관련 이슈 감지
→ Program Lead 1차 확인
→ 필요 시 Growth/Experience Lead와 논의
→ 멘토에게 부담을 최소화하는 방식으로 조율
```

## 8. 운영진 임기·교체·인수인계

### 8.1 권장 원칙

- 역할별 담당 기간을 명시한다.
- 핵심 역할은 단독 담당을 피하고 보조 담당 또는 shadowing 구조를 둔다.
- 운영 문서와 GrowthHub 기록을 인수인계의 기준으로 삼는다.
- 운영진 이탈 시 대체 담당자를 지정한다.
- 신규 운영진은 첫 2주 동안 관찰/보조 업무를 수행한 뒤 독립 역할을 맡는다.

### 8.2 인수인계 문서

- 역할 목적
- 주요 반복 업무
- 정기 일정
- 사용하는 GrowthHub 화면
- 관련 문서/템플릿
- 현재 진행 중인 작업
- 주요 리스크
- 외부 연락처 또는 협업 대상

## 9. 운영 리듬

### 9.1 주간 리듬

- 운영진 주간 회의
- 주요 액션 점검
- 다가오는 일정 확인
- 모집/행사/회계/프로젝트 리스크 확인
- 멘토 지원 필요사항 확인

### 9.2 월간 리듬

- 월간 회고
- 회계 현황 확인
- 학생 참여 상태 점검
- 정기모임 효과 점검
- 시스템 개선사항 정리

### 9.3 기수 리듬

- 모집 준비
- 선발
- 온보딩
- 활동 운영
- 중간 점검
- 발표/회고
- 기수 종료 리포트
- 다음 기수 개선사항 반영

## 10. 현재 판단

Seeds 운영진 구조는 GrowthHub의 하위 문서가 아니라 독립적인 조직 설계 문서로 두는 것이 맞다.

운영진 구조의 핵심은 다음이다.

1. 기능별 책임 구조를 만든다.
2. 멘토의 행정 부담을 줄인다.
3. 운영진은 멘토를 관리하지 않고 지원한다.
4. 의사결정 권한과 escalation 경로를 명확히 한다.
5. 임기, 교체, 인수인계 구조를 둔다.
6. GrowthHub를 업무 실행과 온보딩의 기반으로 활용한다.
