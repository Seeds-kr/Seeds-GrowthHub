# Seeds GrowthHub - 운영시스템 기능 명세 v3

## 1. 문서 목적

이 문서는 GrowthHub 운영 시스템의 기능 범위와 우선순위를 정의한다. 운영 시스템은 Seeds 운영진이 회의, 작업, 모집, 행사, 회계, 공지, 운영 문서, 일정, 운영 리스크를 관리할 수 있도록 돕는 기능군이다.

이 문서는 특정 모집 일정에 직접 종속되지 않는다. 모집/선발 기능은 운영 시스템의 주요 구성요소로 다루되, 특정 모집 실행 상세는 별도 관리한다.

## 2. 운영 시스템의 범위

| 모듈 | 성격 | 우선순위 |
|---|---|---|
| 회의록 관리 | 의사결정과 후속 액션 기록 | 최상 |
| 작업 관리 | 운영 액션 관리 | 최상 |
| 운영 문서/템플릿 | Markdown 기반 문서와 체크리스트 | 최상 |
| 모집/선발 관리 | 지원자, 평가, 면접, 결정 관리 | 높음 |
| 정기모임/행사 관리 | 세션, 행사, 체크리스트, 출석 | 높음 |
| 회계/정산 관리 | 지출, 증빙, 승인, 정산 상태 | 높음 |
| 운영 캘린더 | 회의, 행사, 마감, 정산 일정 | 중상 |
| 공지/커뮤니케이션 | 공지, 이메일, 발송 이력 | 중상 |
| 운영 대시보드 | 지연 작업, 행사 준비, 회계, 운영 리스크 | 중상 |

## 3. 범위 원칙

### 3.1 운영 작업관리와 프로젝트 이슈 관리를 구분한다

운영 시스템의 작업관리는 Jira/Linear를 대체하지 않는다.

다루는 것:

- 회의 후속 액션
- 모집 운영 작업
- 행사/정기모임 준비 작업
- 회계/정산 작업
- 운영 문서 정비
- 운영 개선 작업

다루지 않는 것:

- 학생 프로젝트의 세부 개발 이슈
- 스프린트 단위 개발 관리
- 팀별 Jira/Linear 대체 기능

### 3.2 운영 문서는 Markdown을 기본 형식으로 한다

운영 문서, 템플릿, 체크리스트는 Markdown 기반으로 작성·편집·미리보기 가능해야 한다. DOCX 편집기는 초기 범위에 포함하지 않는다.

### 3.3 운영 시스템은 멘토 관리 도구가 아니다

운영진은 멘토가 학생 성장을 돕는 데 필요한 운영 환경을 지원한다. 운영 시스템은 멘토에게 과도한 행정 보고를 요구하는 방식으로 설계하지 않는다.

## 4. 회의록 관리

### 4.1 주요 기능

- 회의 생성
- 참석자 등록
- 안건 관리
- 논의 내용 기록
- 결정사항 기록
- 보류사항 기록
- 후속 액션 생성
- 관련 객체 연결
- 회의록 Markdown 편집
- 회의록 템플릿 적용
- 수정 이력 관리

### 4.2 Acceptance Criteria

- 회의록에서 Action Item을 생성할 수 있다.
- Action Item에는 담당자, 마감일, 우선순위, 상태가 있어야 한다.
- 회의록은 기수, 행사, 모집, 프로젝트, 회계, 문서와 연결될 수 있다.
- 회의록은 Markdown으로 작성·수정·미리보기 가능하다.
- 운영진 내부 회의록은 권한 있는 사용자만 볼 수 있다.

## 5. 작업 관리

### 5.1 주요 기능

- 작업 생성
- 담당자 지정
- 마감일 설정
- 우선순위 설정
- 상태 변경
- 칸반 보드
- 필터/검색
- 관련 객체 연결
- 지연 작업 알림
- 반복 작업 템플릿

### 5.2 작업 상태

- To Do
- In Progress
- Review
- Blocked
- Done
- Canceled

### 5.3 Acceptance Criteria

- 작업은 회의록, 모집, 행사, 회계, 문서, 프로젝트와 연결될 수 있다.
- 담당자별 작업 목록을 볼 수 있다.
- 마감일이 지난 작업이 대시보드에 표시된다.
- Blocked 상태의 작업은 별도로 표시된다.
- 프로젝트 개발 이슈와 운영 작업은 구분된다.

## 6. 운영 문서/템플릿 관리

### 6.1 주요 기능

- Markdown 문서 작성
- Markdown 문서 편집
- Markdown 미리보기
- 문서 템플릿 생성
- 템플릿 복제
- 체크리스트 문서
- 문서 버전 이력
- 문서 공개 범위 설정
- 기수/행사/회의/모집/회계/프로젝트와 연결
- 외부 링크 첨부
- 파일 첨부

### 6.2 문서 유형

- 운영 매뉴얼
- 회의록 템플릿
- 정기모임 준비 체크리스트
- 모집 운영 체크리스트
- 평가표 템플릿
- 회계 정산 템플릿
- 행사 운영 문서
- 멘토 안내 문서
- 신규 운영진 온보딩 문서

### 6.3 DOCX 원칙

- GrowthHub 내부 source of truth는 Markdown이다.
- DOCX 편집기는 초기 구현 범위에 포함하지 않는다.
- 외부 제출용 문서는 DOCX/PDF export 또는 첨부로 처리한다.
- 서식이 중요한 문서는 Google Drive 또는 파일 첨부로 보관 가능하다.

## 7. 모집/선발 관리

### 7.1 주요 기능

- 모집 캠페인 생성
- 기수 연결
- 지원서 항목 설정
- 지원자 목록 관리
- 상태 필터
- CSV 내보내기
- 평가자 배정
- 서류 평가
- 면접 평가
- 평가 surface 접근 제어
- 면접 일정 관리
- 최종 결정 기록
- 결정 변경 감사 로그
- 합격자 학생 전환
- 활성화 매직링크 발급
- 안내 이메일 발송 이력

### 7.2 현재 구현 반영

현재 구현에는 지원자 목록, 필터, CSV 내보내기, 평가 배정, 면접 일정, 최종 결정, 학생 전환, 활성화 매직링크가 존재한다. 이 구조는 유지하되, GrowthHub의 권한/가시성 원칙과 연결한다.

CSV 내보내기는 formula injection guard를 유지해야 한다.

### 7.3 지원자 상태값

현재 구현의 이중 상태 구조를 존중한다.

legacy status:

- submitted
- reviewing
- interview
- accepted
- rejected
- waitlisted
- withdrawn

application_status:

- submitted
- document_review
- document_review_completed
- interview
- interview_scheduled
- interview_completed
- final_decision_made
- withdrawn

final_decision:

- pending
- accepted
- rejected
- waitlisted
- withdrawn

### 7.4 평가표 구성

평가 항목 예시:

- motivation
- problem_awareness
- initiative
- collaboration
- fit
- overall
- recommendation
- comment

### 7.5 Acceptance Criteria

- 평가자는 자신에게 배정된 지원자만 볼 수 있다.
- 평가자는 배정된 stage에 대해서만 평가를 제출할 수 있다.
- 동일 지원자/평가자/stage 조합은 하나의 평가로 관리된다.
- 최종 결정 변경은 감사 로그에 남는다.
- 합격자는 학생 계정으로 전환될 수 있다.
- 활성화 매직링크는 재발급 시 latest-wins 정책을 따른다.

## 8. 정기모임/행사 관리

### 8.1 주요 기능

- 행사/세션 생성
- 대상 기수/프로그램 연결
- 일정/장소 설정
- 담당자 지정
- 체크리스트 적용
- 참석자 관리
- 출석 기록
- 자료 링크 연결
- 후속 액션 생성
- 회고/만족도 연결
- 회계 정산 연결

### 8.2 행사 단계

| 단계 | 관리 항목 |
|---|---|
| 준비 전 | 목적, 대상, 일정, 장소, 예산, 담당자 |
| 준비 중 | 체크리스트, 자료, 역할분담, 참석예정자 |
| 당일 | 출석, 진행순서, 이슈, 사진/자료 |
| 종료 후 | 회고, 만족도, 후속 액션, 비용정산 |

### 8.3 현재 구현 반영

현재 구현에는 sessions, attendance_records가 존재한다. 이를 Event 개념으로 확장해 정기모임, 워크숍, 발표회, 멘토링 세션을 포괄할 수 있게 한다.

### 8.4 Acceptance Criteria

- 세션은 기수/프로그램과 연결된다.
- 출석을 present/late/absent/excused로 기록할 수 있다.
- 세션에 운영 문서나 체크리스트를 연결할 수 있다.
- 행사 종료 후 후속 액션을 생성할 수 있다.

## 9. 회계/정산 관리

### 9.1 주요 기능

- 수입/지출 등록
- 예산 항목 설정
- 영수증 첨부
- 정산 요청
- 승인/반려
- 지급 완료 처리
- 기수/행사/프로젝트 연결
- 월별/기수별 요약

### 9.2 회계 상태값

- draft
- requested
- under_review
- approved
- paid
- rejected
- canceled

### 9.3 Acceptance Criteria

- 지출에는 금액, 날짜, 항목, 설명, 증빙이 있어야 한다.
- 회계 증빙은 권한 있는 사용자만 볼 수 있다.
- 정산 상태를 관리할 수 있다.
- 지출은 행사, 기수, 프로젝트와 연결될 수 있다.

### 10.1 주요 기능

- 대상 설정: 전체, 기수, 프로그램, 역할

- 발송 성공/실패 이력
- 템플릿 관리

### 10.2 커뮤니케이션 이력 필드

- recipient
- channel
- template_id
- related_object_type
- related_object_id
- sent_at
- status
- failure_reason
- created_by

현재 구현의 announcements와 site_contents는 유지한다. 다만 운영 공지, 공개 사이트 콘텐츠, 이메일 발송 이력의 역할을 구분한다.

## 11. 운영 캘린더

### 11.1 일정 유형

- 운영진 회의
- 모집 일정
- 평가 마감
- 면접 일정
- 정기모임
- 행사
- 정산 마감
- 프로젝트 마일스톤

### 11.2 원칙

초기에는 GrowthHub 내부 일정이 source of truth가 되고, 외부 Calendar는 export 또는 단방향 sync 대상으로 둔다.

## 12. 운영 대시보드

### 12.1 주요 지표

| 영역 | 지표 |
|---|---|
| 작업 | 지연 작업, 담당자별 작업 수, Blocked 작업 |
| 모집 | 지원자 수, 평가 진행률, 면접 확정률, 최종 결정 현황 |
| 행사 | 체크리스트 완료율, 참석 예정자, 후속 액션 |
| 회계 | 월별 지출, 미정산 항목, 승인 대기 항목 |
| 문서 | 업데이트 필요 문서, 최근 수정 문서, 미완료 체크리스트 |
| 성장 연결 | 팀 지원 필요사항, 프로젝트 블로커 |

### 12.2 원칙

운영 대시보드는 감시 도구가 아니라 개입 타이밍을 잡기 위한 운영 보조 도구다.

## 13. 보류할 기능

- Jira/Linear 대체 수준의 프로젝트 이슈 관리
- 복잡한 ERP 수준 회계
- DOCX 내장 편집기
- 모든 외부 커뮤니케이션 통합
- 자동 의사결정
- 성장 점수 기반 운영 판단

## 14. 현재 판단

운영 시스템 v3의 핵심은 다음이다.

1. 회의록, 작업관리, 운영 문서가 운영 실행의 중심이 되어야 한다.
2. 작업관리는 운영 액션 관리에 제한하고 프로젝트 개발 이슈 관리는 대체하지 않는다.
3. 운영 문서는 Markdown 기반 자체 편집·미리보기·버전관리를 지원한다.
4. 모집/선발 기능은 기존 구현을 유지하되, 특정 모집 일정에 종속시키지 않는다.
5. 회계와 행사 기능은 운영 신뢰성과 반복 운영을 위해 필요하다.
6. 외부 연계는 별도 외부 도구 연계 설계 문서를 따른다.
