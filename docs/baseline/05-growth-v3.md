# Seeds GrowthHub - 성장시스템 1차 판단 및 안정 선개발 기능 명세 v3

## 1. 문서 목적

이 문서는 GrowthHub Growth의 최종 설계가 아니라, 학생 성장모델·커리큘럼·운영모델이 확정되기 전에도 유지될 가능성이 높은 성장증거 기록 계층만 다룬다.

따라서 이 문서에서 다루는 프로젝트, 스터디, 산출물, 피드백, 회고, 활동기록은 Seeds 성장시스템 전체가 아니라, 향후 성장모델을 반영하기 위한 선행 데이터 기반이다.

## 2. 현재 작업의 전제

| 구분 | 현재 처리 |
|---|---|
| 성장증거 계층 | 지금 선행 개발 |
| 성장해석 계층 | 성장모델 확정 후 반영 |
| 성장평가 계층 | 보류 |
| 커리큘럼 연계 계층 | 커리큘럼 확정 후 반영 |
| 학생 성장 리포트 | 현재는 활동 요약 수준만 가능 |

## 3. 확정하지 않을 것

- 학생 성장 점수
- 역량별 정량 평가 기준
- 자동 성장 진단
- 커밋 수 기반 기여도 평가
- 학생별 랭킹
- 최종 커리큘럼 구조
- 프로젝트 성과와 개인 역량의 직접 환산 방식
- 성장모델 기반 최종 리포트

## 4. 안정적으로 선개발 가능한 영역

| 영역 | 선개발 가능성 | 이유 |
|---|---|---|
| 프로젝트 기본정보 | 높음 | Seeds 활동의 핵심 단위 |
| 프로젝트 멤버/역할 | 높음 | 협업과 역할 경험의 기반 |
| 스터디 기본정보 | 높음 | 자율 학습 활동 기록 단위 |
| 산출물 링크 | 높음 | 성장 해석의 원자료 |
| GitHub 링크 | 높음 | 개발 프로젝트의 핵심 증거 |
| 발표자료/데모 링크 | 높음 | 결과 공유와 포트폴리오화 가능성 |
| 멘토 피드백 | 높음 | 멘토링 맥락의 누적 |
| 회고 | 높음 | 자기성찰과 다음 목표의 원자료 |
| 참여/출석 | 중간 | 활동 지속성의 참고 신호 |
| 팀 상태 체크 | 높음 | 운영진/멘토 개입 타이밍 판단 |
| 운영진 지원 필요사항 | 높음 | 멘토와 팀을 지원하기 위한 신호 |
| 임시 태그 | 중간 | 최종 성장모델 전까지 분류 보조 |

## 5. MVP 범위 구분

| 구분 | 기능 |
|---|---|
| 선행 개발 필수 | 프로젝트, 프로젝트 멤버/역할, 산출물, 피드백, 활동기록, 기본 가시성 |
| 선행 개발 권장 | 스터디, 회고, 팀 상태 체크, 운영진 지원 필요사항, 임시 태그 |
| 이후 반영 | 성장 리포트, 최종 역량 태그, 커리큘럼 모듈 연결, 멘토 인사이트 대시보드 |
| 보류 | 점수화, 자동평가, 랭킹, GitHub 기반 기여도 판정 |

## 6. 성장증거의 기본 유형

| 성장증거 | 예시 | 해석 주의사항 |
|---|---|---|
| 활동 참여 | 정기모임, 스터디, 발표 | 출석이 곧 성장이라는 의미는 아님 |
| 산출물 | 코드, 발표자료, 데모, 기획서 | 산출물의 존재와 품질 해석은 별도 필요 |
| 역할 경험 | PM, 개발, 발표, 리서치 | 역할명만으로 역량을 단정하지 않음 |
| 피드백 | 멘토, 운영진, 동료 피드백 | 공개 범위와 민감도 고려 필요 |
| 문제 해결 | 블로커, 해결 과정 | 맥락 기록이 중요 |
| 협업 | 역할 분담, 회의, 갈등 조정 | 자동 평가 대상 아님 |
| 자기성찰 | 회고, 다음 목표 | 학생의 선택적 공개 범위 필요 |

### 9.2 가시성 원칙

- private
- student_visible

산출물은 학생 본인, 팀, 프로젝트, 스터디, 과제 제출과 연결될 수 있어야 한다.

## 10. GitHub 및 외부 프로젝트 도구 원칙

GitHub 지표는 평가 점수가 아니라, 멘토링과 회고를 위한 대화 신호로만 사용한다.

Jira, Linear, GitHub Issues, Notion 보드는 학생 팀이 선택한 세부 이슈 관리 도구로 둔다. GrowthHub는 외부 보드 링크, 프로젝트 목표, 마일스톤, 블로커, 산출물 링크만 관리한다.

### 11.2 가시성 원칙

현재 구현의 feedback visibility는 유지하되, 향후 회고와 멘토 노트 정책을 함께 검토한다.

- admin_only

추가 검토:

## 12. 회고 기능

### 12.1 회고 유형

- 개인 회고
- 팀 회고
- 프로젝트 회고
- 스터디 회고
- 행사 후 회고
- 기수 종료 회고

### 12.2 회고 공개 범위 검토

- 개인 회고를 멘토가 볼 수 있는가?
- 운영진은 개인 회고를 볼 수 있는가?
- 학생이 공개 범위를 선택할 수 있는가?
- 팀 회고와 개인 회고의 기본 visibility는 달라야 하는가?
- 회고가 평가에 사용되지 않는다는 원칙을 어떻게 보장할 것인가?

권장 초기값:

| 회고 유형 | 기본 공개 범위 |
|---|---|
| 개인 회고 | private 또는 mentor_visible 검토 |
| 팀 회고 | team_visible 또는 mentor_visible 검토 |
| 프로젝트 회고 | team_visible / mentor_visible / admin_only 중 선택 |
| 기수 종료 회고 | 학생 선택 기반 공개 검토 |

## 13. 임시 태그 정책

현재 구현에는 skill_tags와 tag_mappings가 존재한다. 다만 성장모델 확정 전에는 이를 최종 역량 태그로 고정하지 않는다.

초기 태그 예시:

- 프로젝트
- 협업
- 기술학습
- 발표
- 회고
- 운영참여
- 문제정의
- 산출물
- 멘토링

주의사항:

- 태그를 역량 점수로 해석하지 않는다.
- 태그를 학생 평가 기준으로 사용하지 않는다.
- 최종 성장모델이 확정되면 태그 체계를 재정의할 수 있다.

## 16. 현재 판단

GrowthHub Growth의 초기 목표는 성장평가가 아니라 성장증거 축적이다. 현재 선개발 범위는 프로젝트, 스터디, 산출물, GitHub 링크, 피드백, 회고, 활동기록, 팀 상태 체크, 임시 태그에 제한한다.

향후 성장모델·커리큘럼·운영모델이 정렬되면 이 증거들을 성장해석 계층과 연결한다.
