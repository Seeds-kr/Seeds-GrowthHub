# Seeds GrowthHub - Overview v3

## 1. 문서 목적

이 문서는 Seeds GrowthHub의 상위 목적, 문제 범위, 구조, 설계 원칙, 사용자 가치 후보를 정의한다. 세부 기능, 데이터 모델, 화면 구조, 구현 작업 큐를 확정하는 문서가 아니라, GrowthHub가 무엇을 다루고 무엇을 아직 확정하지 않는지를 구분하는 기준 문서다.

## 2. GrowthHub 정의

Seeds GrowthHub는 Seeds의 운영관리와 학생 성장증거 축적을 연결하는 내부 운영·성장 인프라다.

GrowthHub는 단순 운영툴, LMS, 프로젝트 관리툴, 그룹웨어 중 하나가 아니다. Seeds의 운영 실행, 문서화, 의사결정 추적, 산출물 기록, 피드백 누적, 성장 해석 기반을 연결하는 시스템이다.

## 3. 상위 구조

```text
Seeds GrowthHub
├─ Core 기반 계층
├─ 운영 시스템 / GrowthHub Ops
└─ 성장 시스템 / GrowthHub Growth
```

| 구분 | 성격 | 주요 내용 |
|---|---|---|
| Core 기반 계층 | 운영 시스템과 성장 시스템의 공통 기반 | 사람, 역할, 권한, 기수, 팀, 문서, 알림, 데이터 구조, 연동, 가시성 |
| 운영 시스템 | Seeds 운영 실행을 돕는 시스템 | 회의, 작업, 모집, 행사, 회계, 공지, 운영 문서, 운영 대시보드 |
| 성장 시스템 | 학생 성장증거를 기록하고 해석 가능하게 하는 시스템 | 프로젝트, 스터디, 산출물, 피드백, 회고, 활동기록, 성장 리포트 기반 |

Core는 운영 시스템과 성장 시스템과 동급의 하위 기능이 아니라 두 시스템이 공유하는 기반 계층이다.

## 4. 현재 작업의 성격

GrowthHub 구축은 완성된 논리를 그대로 구현하는 작업이 아니다.

현재 작업은 두 흐름을 병행한다.

1. 논리의 방향성과 직관은 있으나 아직 구체화되지 않은 영역은, 우선 작동 가능한 형태로 구현하고 실제 화면을 보며 빠르게 보완한다.
2. 논리의 방향성 자체가 아직 열린 영역은, 기존 논의와 현재까지의 직관을 바탕으로 바뀌지 않을 가능성이 높은 선행 구조만 먼저 개발한다.

따라서 각 문서는 다음 근거 수준을 구분해야 한다.

| 구분 | 의미 |
|---|---|
| 확정 | 논의되었고 현재 방향과 부합하여 유지 가능성이 높은 것 |
| 임시 구체화 | 방향성은 있으나 구체 논리가 미완성되어 우선 구현해보는 것 |
| 선행 개발 가능 | 성장모델·운영모델이 바뀌어도 유지될 가능성이 높은 기반 |
| 검토 필요 | 아직 사고를 제한하면 안 되는 열린 영역 |
| 보류 | 지금 구현하면 방향을 부적절하게 고정할 수 있는 영역 |

## 5. GrowthHub가 다루는 문제 범위

### 5.1 Seeds 운영·성장 문제 전체와 시스템 부재 문제의 구분

GrowthHub 문서는 Seeds의 운영모델, 성장모델, 커리큘럼, 역할구조의 최종 논리를 확정하지 않는다. 이 문제들은 별도 논의에서 다룬다.

GrowthHub가 직접 다루는 것은 그 논의가 실제 운영과 성장 기록으로 이어지도록 만드는 시스템 기반이다.

| 구분 | GrowthHub Overview에서의 처리 |
|---|---|
| Seeds 성장모델 자체 | 확정하지 않음 |
| 커리큘럼 구조 | 확정하지 않음 |
| 운영모델/역할구조 | 확정하지 않음 |
| 멘토링 구조 | 확정하지 않음 |
| 시스템 부재로 인한 실행·기록·누적 문제 | 다룸 |
| 향후 성장모델을 반영할 기반 | 다룸 |

### 5.2 시스템 부재로 인해 발생할 수 있는 운영 실행 문제

- 회의 결정사항이 후속 액션으로 연결되지 않음
- 담당자와 마감일이 불명확해짐
- 운영 문서와 체크리스트가 흩어짐
- 모집, 행사, 회계, 정기모임 이력이 누적되지 않음
- 신규 운영진이 과거 운영 맥락을 파악하기 어려움
- 역할과 권한이 시스템에 반영되지 않음
- 운영 리스크를 조기에 발견하기 어려움

### 5.3 시스템 부재로 인해 발생할 수 있는 성장 기록 문제

- 프로젝트, 산출물, 피드백, 회고가 흩어짐
- 학생 성장 궤적을 보기 어려움
- 멘토 피드백이 일회성으로 사라짐
- 팀 상태와 블로커가 누적되지 않음
- 성장모델 확정 후 해석할 데이터가 부족함
- 학생이 자신의 경험을 포트폴리오화하기 어려움

## 6. 설계 원칙

### 6.1 운영은 안정화하고, 성장은 성급히 점수화하지 않는다

GrowthHub는 운영 실행을 안정화하되, 성장모델이 확정되기 전에는 학생 성장을 점수화하지 않는다. 먼저 활동, 산출물, 피드백, 회고, 역할 경험 같은 성장증거를 기록한다.

### 6.2 멘토의 행정 부담을 최소화한다

멘토는 관리자가 아니라 학생 성장을 돕는 조력자다. GrowthHub는 멘토에게 긴 보고서를 요구하기보다, 담당 팀의 상태를 빠르게 파악하고 짧게 피드백을 남길 수 있게 해야 한다.

### 6.3 기존 도구를 대체하지 않고 연결한다

Discord, GitHub, Jira, Notion, Google Drive 등 기존 도구를 무리하게 대체하지 않는다. GrowthHub는 Seeds 관점에서 필요한 메타데이터, 결정사항, 산출물 링크, 상태, 피드백을 관리한다.

### 6.4 내부 문서와 운영 지식을 시스템화한다

GrowthHub는 운영진 온보딩과 인수인계를 돕는 지식 기반이어야 한다. 운영 문서, 템플릿, 체크리스트는 Markdown 기반으로 작성·수정·버전 관리 가능해야 한다.

### 6.5 확정된 것과 열린 것을 구분한다

GrowthHub 문서는 향후 성장모델·커리큘럼·운영모델 논의를 제한하지 않아야 한다. 따라서 각 기능과 판단은 확정, 임시 구체화, 선행 개발 가능, 검토 필요, 보류로 구분한다.

## 7. 사용자별 추가 검토 가치 후보

이 섹션은 GrowthHub가 반드시 제공한다고 확정한 가치가 아니라, 설계 과정에서 추가로 검토해야 할 사용자 경험 후보를 정리한다.

| 사용자 | 추가 검토 가치 후보 | 현재 판단 |
|---|---|---|
| 학생 | 성장 궤적 가시화, 산출물 정리, 회고 축적, 공개 피드백 확인, 포트폴리오화 | 성장증거 계층과 직접 연결되므로 핵심 후보 |
| 멘토 | 담당 팀 상태 파악, 이전 피드백 확인, 멘토링 기억 보조, 운영진 지원 요청 | 멘토 부담 최소화 원칙과 정렬 |
| 운영진 | 운영 누락 감소, 신규 운영진 온보딩, 리스크 조기 발견, 문서/체크리스트 기반 운영 | 운영 지속가능성과 직접 연결 |
| Seeds 조직 | 기수별 개선, 외부 협력 신뢰 확보, 운영 지식 축적, 멘토 의존도 완화 | 중장기 가치 후보 |
| 외부 파트너 | 프로젝트/협업 정보의 제한적 확인, Seeds 운영 신뢰 확인 | 향후 외부 협력 확대 시 검토 |
| 알럼나이 | 졸업생 연결, 후배 지원, 프로젝트/멘토링 참여 | 현재 범위에서는 보류 가능 |

## 9. 현재 판단

Seeds GrowthHub는 운영 시스템과 성장 시스템을 모두 포함하지만, 지금 단계에서 모든 운영모델과 성장모델을 확정하지 않는다.

우선순위는 다음과 같다.

1. Core 기반을 정리한다.
2. 운영 실행에 필요한 기능을 안정화한다.
3. 성장모델 확정 전에도 유지될 성장증거 구조를 선개발한다.
4. 별도 논의에서 성장모델, 커리큘럼, 운영모델, 역할구조를 정렬한다.
5. 그 결과를 GrowthHub Growth와 운영 구조에 반영한다.
