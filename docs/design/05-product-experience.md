## 1. 이 문서가 채우는 공백

01~04는 데이터·권한·API를 정했지만 **"이걸 쓰는 경험이 어떤가"** 는 정하지 않았다. 그 결과 코드에는 아무도 결정한 적 없는 답이 굳어 있었다.

| 모듈 | 결정된 적 없이 굳어 있던 것 |
|---|---|
| 회의록 | 고정 4섹션 + plain `Textarea` + `react-markdown` 렌더 |
| 문서 | 단일 마크다운 + 좌우 분할 + 버전 사이드바 |
| 작업 | 칸반처럼 보이지만 드래그 없음 (Select로 상태 변경) |
| 액션 아이템 | 회의록 본문이 아니라 별도 다이얼로그에서 생성 |
| **알림** | **아예 없음** — 대시보드를 열지 않으면 아무도 모름 |

이 문서가 그 공백을 메운다.

## 2. 결정 기록

### ADR-005 — 마크다운을 유지하되 툴바를 붙인다

**결정.** 저장 형식은 마크다운 그대로. 그 위에 서식 툴바·단축키·이미지 붙여넣기 업로드를 얹는다. 블록 에디터(Tiptap/BlockNote 등)는 도입하지 않는다.

**근거.** Core v2 §8.1이 마크다운을 source of truth로 삼은 이유 — 버전 이력, 템플릿 복제, PDF/DOCX export, 체크리스트 결합 — 이 전부 블록 에디터를 도입하면 다시 설계해야 한다. 툴바는 그 자산을 하나도 건드리지 않으면서 진입장벽만 없앤다.

**대가.** 노션에 익숙한 사람에게는 여전히 한 단계 낮은 경험이다. 표 편집이 특히 불편하다. → 표는 툴바에서 골격을 삽입해주고, 정말 서식이 중요한 문서는 Drive 링크로 붙인다(Core v2 §9.1의 hybrid 전략).

---

### ADR-006 — 회의록은 유형별 템플릿, 결정·액션은 공통 강제

**결정.** `meetings.meetingType`(general·ops·planning·retro·mentor·external)에 따라 섹션 프리셋을 다르게 채운다. 단, **결정사항과 액션 아이템은 모든 템플릿에 공통으로 강제**한다.

**근거.** 고정 4섹션은 기획 회의·회고에 맞지 않고, 완전 자유는 결정사항 추출을 작성자 역량에 맡기게 된다. 유형별 템플릿은 둘 사이다. 결정·액션만 공통으로 두면 인수인계와 감사에 필요한 최소 구조는 항상 보장된다.

**대가.** 템플릿 6종을 유지보수해야 한다. → `documents`의 `is_template` 구조를 재사용해 운영진이 직접 고칠 수 있게 한다. 코드에 하드코딩하지 않는다.

---

### ADR-007 — 알림은 Discord 웹훅 + 인앱 배지

**결정.** 운영진 공개 채널에 웹훅으로 알리고, 인앱은 배지로 보완한다. 이메일은 지금 쓰지 않는다.

**근거.** Seeds는 이미 Discord에서 산다. 도달률이 가장 높고, 멘토가 데스크톱 앞에 없을 때도 신호를 받는다(§5.4 참조 — 모바일을 포기한 결정을 상쇄한다).

**경계 — 이게 감시가 되지 않게 하는 규칙:**
- **공개 채널에만** 보낸다. 개인 DM 없음.
- 학생 개인정보·평가정보·회고 내용을 **절대 페이로드에 넣지 않는다.**
- 알림은 "무슨 일이 있다 + 링크"까지만. 내용은 GrowthHub에서 권한 확인 후 본다.
- 학생 개인에게 가는 알림은 만들지 않는다. 운영진·멘토 대상만.

**대가.** Discord가 죽으면 알림이 끊긴다. → 인앱 배지가 항상 병행되므로 GrowthHub 자체 기능은 멈추지 않는다(외부연계 §12 원칙).

---

### ADR-008 — 데스크톱 우선, 모바일은 읽기 보장

**결정.** 데스크톱을 기준으로 설계한다. 모바일에서는 **깨지지 않고 읽히는 것**까지만 보장하고, 편집·복잡 인터랙션은 지원하지 않는다. 모바일 레이아웃이 애매해지는 화면은 **데스크톱 전용으로 명시**한다.

**근거.** admin 화면은 표·칸반·분할 편집기가 많아 전면 반응형은 비용이 크고 데스크톱 경험을 타협시킨다.

**대가.** 멘토가 폰에서 상태체크를 못 한다. 본업이 있는 현직 개발자에게는 입력 장벽이다. → ADR-007의 Discord 알림이 "지금 확인이 필요하다"는 신호를 전달하고, 실제 입력은 데스크톱에서 한다. **이 조합이 깨지면(알림 미도입) 상태체크 입력률을 재검토해야 한다.**

## 3. 편집 경험

### 3.1 컴포넌트

새 의존성을 추가하지 않는다. 기존 `Textarea` + `react-markdown` 위에 얇은 툴바를 얹은 `MarkdownEditor` 하나를 만든다.

```text
artifacts/seeds/src/components/markdown/
  MarkdownEditor.tsx     툴바 + Textarea + 미리보기 토글
  MarkdownToolbar.tsx    버튼 → 커서 위치에 마크다운 삽입
  useMarkdownInsert.ts   selection 보존 삽입 로직
  MarkdownView.tsx       react-markdown 렌더 (기존 MarkdownBlock 대체)
```

**`@uiw/react-md-editor` 같은 기성 에디터를 쓰지 않는 이유:** 자체 테마를 들고 와서 shadcn/ui와 충돌하고, 다크모드·폰트(Pretendard)를 다시 맞춰야 한다. 툴바는 150줄 남짓이라 직접 만드는 편이 싸다.

### 3.2 툴바 구성

| 그룹 | 버튼 | 단축키 |
|---|---|---|
| 텍스트 | 굵게 · 기울임 · 취소선 · 인라인 코드 | ⌘B · ⌘I · — · ⌘E |
| 블록 | 제목(H2/H3) · 인용 · 코드블록 · 구분선 | — |
| 목록 | 순서 없음 · 순서 있음 · **체크리스트** | ⌘⇧8 · ⌘⇧7 · ⌘⇧9 |
| 삽입 | 링크 · 표 · 이미지 | ⌘K · — · — |

**체크리스트를 툴바 1급으로 올리는 이유:** Ops v3 §6이 요구하는 행사 준비 체크리스트·모집 운영 체크리스트가 전부 `- [ ]` 문법이다. 이게 묻히면 체크리스트 문서 기능이 사실상 안 쓰인다.

### 3.3 이미지 붙여넣기

```text
클립보드 붙여넣기 / 드래그앤드롭
  → POST /admin/attachments  (multipart)
  → attachments 행 생성 (linkedObjectType='document'|'meeting', visibility=admin_only)
  → 응답 URL 을 커서 위치에 ![](url) 삽입
```

⚠️ **[04 §5 `attachments`](04-core-infra.md)에 의존한다.** 그 전까지 툴바는 이미지 버튼을 비활성으로 두고 "외부 링크 붙여넣기"만 안내한다.

### 3.4 편집 모드

| 화면 | 배치 |
|---|---|
| 문서 상세 | 좌우 분할 (편집 │ 미리보기) — **현행 유지** |
| 회의록 섹션 | 섹션별 인라인 편집. 미리보기는 탭 토글 (분할하면 섹션이 너무 좁다) |
| 회고 (학생) | 단일 편집 + 미리보기 토글 |
| 짧은 입력 (상태체크 코멘트 등) | 툴바 없는 plain `Textarea` |

**모든 마크다운 입력에 툴바를 붙이지 않는다.** 한 줄짜리 입력에 툴바는 소음이다.

## 4. 회의록 템플릿

### 4.1 유형별 프리셋

공통 필수 = **결정사항 · 액션 아이템**. 아래 표에서 굵은 것이 그 둘이다.

| meetingType | 섹션 프리셋 |
|---|---|
| `general` 일반 | 안건 · 논의 · **결정사항** · 보류 · **액션** |
| `ops` 운영 | 지난 액션 점검 · 이번 주 운영 현황 · 리스크 · **결정사항** · **액션** |
| `planning` 기획 | 배경/문제 · 옵션 검토 · 트레이드오프 · **결정사항** · **액션** |
| `retro` 회고 | 잘된 것 · 아쉬운 것 · 배운 것 · **결정사항** · **액션** |
| `mentor` 멘토 | 팀별 상태 공유 · 멘토 요청사항 · 운영 지원 필요 · **결정사항** · **액션** |
| `external` 외부 | 참석자/소속 · 논의 내용 · 합의사항 · **결정사항** · **액션** |

### 4.2 구현 방식 — 하드코딩하지 않는다

템플릿은 코드가 아니라 **`documents` 테이블의 `is_template=true` 행**으로 둔다.

```text
documents (is_template=true, docType='meeting_note')
  title:      "운영 회의록 템플릿"
  contentMd:  "## 지난 액션 점검\n\n## 이번 주 운영 현황\n..."
  linkedObjectType: 'meeting_type'      ← 신규 화이트리스트 값
  linkedObjectId:   null
```

`meetings` 생성 시 유형을 고르면 해당 템플릿의 `contentMd`를 본문 초안으로 복사한다. 운영진이 `/admin/documents`에서 템플릿을 직접 고칠 수 있고, 코드 배포 없이 반영된다.

### 4.3 스키마 영향 — 마이그레이션 있음

현행 `meetings`는 4개 고정 컬럼(`agendaMd`·`decisionsMd`·`pendingMd`·`notesMd`)이다. 유형별 가변 섹션과 맞지 않는다.

```ts
// meetings 에 추가
bodyMd: text("body_md").notNull().default(""),   // 템플릿 기반 자유 본문
// decisionsMd 는 유지 — 공통 강제 필드이므로 별도 컬럼이 맞다
```

**이관 정책 (비파괴):**
1. `bodyMd` 컬럼을 추가한다. 기존 4개 컬럼은 **삭제하지 않는다.**
2. 백필: `bodyMd = "## 안건\n{agendaMd}\n\n## 보류\n{pendingMd}\n\n## 메모\n{notesMd}"`
3. `decisionsMd`는 그대로 둔다 — 대시보드·감사에서 결정사항만 뽑는 쿼리가 살아 있어야 한다.
4. UI는 `bodyMd` + `decisionsMd` 2필드로 전환한다.
5. 구 컬럼은 한 기수 운영해보고 문제 없으면 제거한다.

**액션 아이템은 지금처럼 별도 다이얼로그를 유지한다.** 본문에서 `- [ ]`를 파싱해 `ops_tasks`로 자동 승격하는 방식은 담당자·마감일을 잡을 수 없어 반쪽이 된다.

## 5. 알림

### 5.1 알림 이벤트

| # | 이벤트 | 수신 | 채널 | 시점 |
|---|---|---|---|---|
| N1 | 작업 마감 초과 | 운영진 채널 | Discord + 배지 | 매일 09:00 요약 |
| N2 | 작업이 `blocked` 로 전환 | 운영진 채널 | Discord | 즉시 |
| N3 | **팀 지원 요청** (`needsOpsSupport`) | 운영진 채널 | Discord + 배지 | 즉시 |
| N4 | 상태체크 14일 경과 팀 | 멘토 채널 | Discord | 주 1회 월요일 |
| N5 | 정산 승인 대기 | 운영진 채널 | Discord + 배지 | 매일 요약 |
| N6 | 평가 마감 임박 (모집 기간) | 운영진 채널 | Discord | 마감 3일 전·1일 전 |
| N7 | 다가오는 행사 (D-3) | 운영진 채널 | Discord | 매일 요약에 포함 |

**N3이 가장 중요하다.** 멘토가 올린 지원 요청이 즉시 운영진에게 닿아야 [02 Mentor Workspace](02-mentor-workspace.md)의 30초 상태체크가 의미를 갖는다. 그게 없으면 멘토는 "말해도 아무 일도 안 일어난다"고 학습한다.

**만들지 않는 알림:** 학생 개인 대상 알림, 멘토 개인 DM, 학생 활동 요약, 회고 작성 독촉.

### 5.2 Discord 웹훅 — 새 테이블 없음

```text
SEEDS_DISCORD_OPS_WEBHOOK_URL      운영진 채널
SEEDS_DISCORD_MENTOR_WEBHOOK_URL   멘토 채널 (선택)
```

- 발송 이력은 [04 §6 `communication_logs`](04-core-infra.md)에 `channel='discord'`로 남긴다. **신규 테이블이 필요 없다.**
- 웹훅 URL 미설정 시 조용히 건너뛴다(`logger.debug`). 알림 실패가 본 기능을 막지 않는다.
- 재시도는 1회까지. 실패는 `communication_logs.status='failed'` + `failureReason`.

**페이로드 규칙 (엄수)**

```json
{
  "content": "🔴 팀 지원 요청 · 3기 프로젝트 「알림봇」",
  "embeds": [{
    "description": "담당 멘토가 운영진 지원을 요청했습니다.",
    "url": "https://<host>/admin/projects/42"
  }]
}
```

- 팀명·프로젝트명·기수까지만. **학생 이름·평가 내용·회고·블로커 원문을 넣지 않는다.**
- 링크를 눌러 GrowthHub에서 권한 확인 후 본다.

### 5.3 인앱 배지 — 새 테이블 없음

`GET /admin/ops-dashboard/summary`가 이미 반환하는 값을 재사용한다. 사이드바 메뉴 옆에 숫자만 띄운다.

| 메뉴 | 배지 |
|---|---|
| 작업 | 지연 + blocked 합계 |
| 운영 대시보드 | 미해결 팀 지원 요청 |
| 재정 | 승인 대기 (`finance` 보유자에게만) |

**읽음 처리를 만들지 않는다.** 배지는 "지금 열려 있는 건수"이지 알림함이 아니다. `notifications` 테이블이 필요 없어진다.

### 5.4 스케줄 실행

일일/주간 요약은 별도 워커 없이 처리한다.

```text
GET /internal/cron/daily-digest   (헤더 시크릿 인증)
  → N1 · N5 · N7 집계 → Discord 발송 → communication_logs 기록
```

Replit Scheduled Deployments 또는 외부 cron이 호출한다. 즉시 알림(N2·N3)은 해당 mutation 라우트에서 직접 호출한다.

## 6. 반응형 정책

### 6.1 3단계 등급

모든 화면은 셋 중 하나로 분류하고, 신규 화면 추가 시 등급을 명시한다.

| 등급 | 의미 | 대상 |
|---|---|---|
| **A · 모바일 읽기 보장** | 레이아웃 안 깨짐, 가로 스크롤 없음, 내용 전부 읽힘. 편집은 불가 | 학생 전 화면, 멘토 조회 화면, 공개 사이트 |
| **B · 모바일 열람 가능** | 표는 카드로 접히거나 `overflow-x` 스크롤. 최소한의 조작만 | Admin 목록·상세 조회 |
| **C · 데스크톱 전용** | 좁은 화면에서 안내 배너 표시 후 기능 차단 | 칸반, 분할 편집기, 넓은 표, 출석 일괄 입력 |

### 6.2 화면별 등급

```text
A  공개 사이트 전체 · /student/* 전체 · /mentor/teams · /mentor/projects/:id (조회부)
B  /admin 목록 화면 · /admin/*/:id 상세 조회 · /admin/ops-dashboard
C  /admin/tasks (칸반) · /admin/documents/:id (분할 편집) · /admin/meetings/:id (편집 모드)
   /admin/sessions/:id/attendance (일괄 출석) · /mentor/projects/:id 상태체크 폼
```

### 6.3 C 등급 처리

```tsx
// 좁은 화면에서 차단 + 안내. 빈 화면이나 깨진 레이아웃을 보여주지 않는다.
<DesktopOnly feature="작업 보드">
  <TaskKanban />
</DesktopOnly>
```

> 이 화면은 데스크톱에 최적화되어 있습니다. 넓은 화면에서 열어주세요.

**규칙: 애매하면 C로 내린다.** 어중간한 모바일 대응은 깨진 화면을 보여주는 것보다 낫지 않다.

### 6.4 기준선

- 브레이크포인트는 Tailwind 기본값을 쓴다. C 등급 차단 기준은 `lg`(1024px) 미만.
- A·B 등급은 **가로 스크롤 금지**. 표는 `overflow-x-auto` 컨테이너 안에서만 스크롤한다.
- 사이드바는 현행 모바일 드로어를 유지한다.

## 7. 이 문서에서 함께 정한 나머지

물어보지 않고 정했다. 뒤집을 만한 게 있으면 알려달라.

| 항목 | 결정 | 근거 |
|---|---|---|
| 작업 보드 드래그앤드롭 | **도입한다** | 칸반 모양인데 드롭다운으로만 옮기는 건 어긋난다. C 등급(데스크톱 전용)이므로 터치 대응 부담도 없다 |
| 회고 작성 방식 | **자유 서술 + 선택적 프롬프트** | 유형 선택 시 질문 3개를 placeholder로 제안하되 강제하지 않는다. 양식을 강제하면 형식적 답변이 는다 |
| 전역 검색 | **보류** | 데이터가 쌓이기 전 검색 UX는 과설계다. 각 목록 화면의 필터로 충분하다 |
| 신규 운영진 첫 화면 | **`/admin` 대시보드에 온보딩 카드** | 별도 온보딩 화면 대신, `documents`의 온보딩 문서로 연결하는 카드를 담당 기능 역할에 맞춰 띄운다 |
| 액션 아이템 자동 추출 | **하지 않는다** | 담당자·마감일이 빠져 반쪽이 된다 (§4.3) |

## 8. 수용 기준

- [ ] 마크다운을 모르는 사람이 툴바만으로 제목·목록·체크리스트·링크를 넣을 수 있다.
- [ ] 툴바 삽입 후 커서 위치와 선택 영역이 보존된다.
- [ ] 이미지 붙여넣기가 `attachments`로 업로드되고 `admin_only`로 저장된다. (04 이후)
- [ ] 회의 유형을 고르면 해당 템플릿 본문이 초안으로 채워진다.
- [ ] 템플릿을 `/admin/documents`에서 수정하면 다음 회의부터 반영된다 (코드 배포 없이).
- [ ] `meetings` 마이그레이션 후 기존 회의록의 안건·보류·메모 내용이 `bodyMd`에서 전부 보인다.
- [ ] `decisionsMd`가 유지되어 결정사항 추출 쿼리가 회귀 없이 동작한다.
- [ ] 멘토가 `needsOpsSupport` 상태체크를 올리면 운영진 Discord 채널에 즉시 뜬다.
- [ ] Discord 페이로드에 학생 이름·평가·회고·블로커 원문이 **없다**.
- [ ] 웹훅 URL 미설정 상태에서 모든 기능이 정상 동작한다.
- [ ] Discord 발송이 `communication_logs`에 남고, 실패 시 `failureReason`이 기록된다.
- [ ] 학생 개인에게 가는 알림이 **없다**.
- [ ] A 등급 화면이 375px에서 가로 스크롤 없이 읽힌다.
- [ ] C 등급 화면이 좁은 화면에서 깨진 레이아웃 대신 안내를 보여준다.
