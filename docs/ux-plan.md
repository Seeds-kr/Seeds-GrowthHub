# UX·디자인 개선 계획

> 작성 2026-08-03. 근거: 사용자 피드백("호버해도 아무 변화가 없어 클릭되는 버튼인지 모르겠다",
> "색상이나 전체 디자인이 좋지 않다") + `PRODUCT.md`에서 확정한 제품 진실.

## 왜 이 순서인가

**스토리 → 기반 → 적용 → 인프라** 순이다.

디자인부터 손대면 어느 화면이 중요한지 모른 채 다듬게 된다. 반대로 스토리만 걷고
개별 화면을 땜질하면 호버 없음 같은 **체계적 결함**은 화면 수만큼 반복된다.
그래서 스토리로 **범위를 먼저 확정**하고, 토큰·상태를 **한 번 고치고**, 그 위에서
스토리별 문제를 잡는다.

---

## 1단계 — 유저 스토리 확정과 실제 주행

목적: 무엇을 고쳐야 하는지를 의견이 아니라 **주행 기록**으로 만든다.

`PRODUCT.md`의 세 사용자(틈새·전담·신규)가 동시에 존재한다는 사실이 판정 기준이다.
같은 화면이라도 **신규가 헤매면 실패**로 적는다.

| # | 스토리 | 역할 |
|---|---|---|
| S1 | 회의를 열고 회의록을 남긴 뒤 액션 아이템을 담당자에게 배정한다 | 운영진 |
| S2 | 공지를 작성해 특정 기수에 게시한다 | 운영진 |
| S3 | 모임을 만들고 당일 출석을 체크한다 | 운영진 |
| S4 | 지원서를 검토하고 면접을 잡고 최종 결정을 내려 학생으로 전환한다 | 모집 담당 |
| S5 | 새 운영진이 처음 로그인해서 자기가 할 일을 찾는다 | 신규 운영진 |
| S6 | 담당 팀 상태를 확인하고 30초 상태체크를 올린다 | 멘토 |
| S7 | 학생이 과제를 확인하고 제출한다 | 학생 |
| S8 | 학생이 회고를 쓰고 공개 범위를 정한다 | 학생 |

각 스토리마다 기록한다: **클릭 수 · 막힌 지점 · 되돌아간 횟수 · 추측해야 했던 것**.
Playwright로 실제 주행하고 스크린샷을 남긴다.

산출물: `docs/ux-findings.md` (스토리별 결함 목록, 심각도 순)

## 2단계 — 시각 기반 확정 (DESIGN.md)

목적: 색·타이포·간격·상태를 **한 곳에서** 정하고 화면마다 재발명하지 않게 한다.

여기서 결정이 하나 필요하다.

- **문서화(document)** — 지금 시각 체계를 정본으로 굳히고 그 위에서 다듬는다. 안전하고 빠르다.
- **교체(new-work)** — "전체 디자인이 좋지 않다"를 그대로 받아 시각 세계를 새로 정한다.
  기능·문구·구조는 보존하고 겉모습만 교체한다. 비용이 크고 되돌리기 어렵다.

피드백 문구는 교체 쪽에 가깝지만, **되돌리기 비싼 결정**이므로 1단계 기록을 보고
함께 정한다. 브랜드 제약(Pretendard, 학생 개발자 동아리 톤, 리더십·서예풍 금지)은
어느 쪽이든 유지된다.

## 3단계 — 인터랙션 상태 일괄 수정

사용자가 직접 지적한 것이고 **체계적 결함**이라 개별 화면이 아니라 컴포넌트에서 고친다.

- 모든 클릭 가능 요소에 hover·focus-visible·active·disabled 상태
- 키보드 포커스 링 (지금 눈으로 확인 불가)
- 상태 변화에 걸리는 시간과 커서 모양
- 색만으로 상태를 알리지 않기 (PRODUCT.md 접근성 항목)

검증: `npx impeccable detect`로 기계 검사 + Playwright로 호버 전후 스타일 비교.

## 4단계 — 스토리별 UX 수정

1단계에서 나온 결함을 심각도 순으로 처리한다. 2·3단계가 끝난 뒤라 기반 위에서 고친다.
빈 상태(다음 행동 안내 없음)가 여기 포함된다.

## 5단계 — 프로덕션 인프라

기능이 아니라 **시한이 있는 것**이다. 실데이터가 들어가기 전에 해야 하고 그 뒤엔 비용이 급등한다.

- **마이그레이션 파일** — 지금은 `drizzle-kit push` 전용이라 버전도 리뷰할 diff도 없다.
  실데이터 위에서 컬럼을 조용히 드롭할 수 있다.
- **자체호스팅 정비** — 현재 프리뷰 DB는 스모크 테스트용 컨테이너다. 볼륨·백업·systemd 없음.
  여기에 실제 기수 데이터가 쌓이기 시작하면 되돌릴 수 없다.
- **e2e 확장** — 지금은 반응형만 덮는다. 403/404 권한 경계는 curl로만 확인했다.

  목록 스캔이 더 빠르다.
