Part 1. Self-Audit

Create a compliance checklist for prompts 0~6.

For each implemented area, report:
- Requirement / Acceptance Criteria
- Current status: Pass / Partial / Fail / Deferred
- Evidence: route, screen, file, table, or behavior
- Fix needed: yes/no
- Risk level

Audit these areas:

A. Admin IA / Navigation
- Admin navigation is grouped into Home, Core, Ops, Growth, Content, System.
- Existing routes are preserved.
- Existing implemented pages are not replaced by placeholders.
- Placeholder pages only exist for truly unimplemented future features.
- Placeholder pages clearly explain purpose, current status, and why deferred.
- Core/Ops/Growth terminology matches the baseline.

B. Core section
- Users/Members route to actual existing user/member functionality if available.
- People Profiles route to actual existing people/profile management.
- Cohorts route to actual existing cohort management.
- Programs route to actual existing program management, with note that Program meaning may be redefined later.
- Students/Members route to existing student/member management if already implemented.
- Roles & Permissions at least shows a read-only overview of the current role model:
  - admin
  - mentor
  - student
  - extra_roles
  - effective roles
  - evaluator surface is assignment-based, not a separate role
  - scope-based role_assignments are deferred/future scope.
- Core should not appear incomplete where existing functionality already exists.

C. Meetings + Tasks
- Admin can create meeting.
- Admin can edit meeting.
- Meeting supports Markdown fields for agenda, decisions, notes, pending items.
- Meeting detail page allows creating follow-up Action Items directly.
- Created Action Items automatically store source_type=meeting and source_id=current meeting.
- Related Action Items appear on Meeting detail page.
- Created Action Items appear in Tasks list/board.
- Task has title, assignee, due date, priority, status.
- Task supports statuses: todo, in_progress, review, blocked, done, canceled.
- Overdue and blocked tasks are identifiable.
- Tasks are operational tasks, not student project issue tracking.

D. Documents / Templates / Checklists
- Admin can create Markdown document.
- Admin can edit and preview Markdown.
- Admin can mark document as template.
- Admin can clone template into a new document.
- Version history is created when content changes.
- Document visibility exists and is enforced.
- Checklist-style documents are usable for operations.
- Internal documents are not visible to students.
- DOCX editor is not implemented; this is intentional.

E. Events / Sessions
- Existing sessions still work.
- Session/event can be connected to cohort/program.
- Session/event detail can link checklist document/template.
- Attendance behavior remains compatible with existing student views.
- Admin can create follow-up tasks from session/event detail.
- Materials/external links can be attached or linked if implemented.
- Students only see sessions relevant to their cohort/program and visibility rules.

F. Finance / Attachments
- Admin/Finance user can create finance record.
- Finance record includes amount, category, date, description, requester, status.
- Receipt URL or attachment exists.
- Finance record can link to event/session, cohort, project, or document if feasible.
- Status values exist: draft, requested, under_review, approved, paid, rejected, canceled.
- Finance information is not visible to students.
- Restricted access is enforced.

G. Ops Dashboard
- Dashboard shows overdue tasks.
- Dashboard shows blocked tasks.
- Dashboard shows upcoming events/sessions.
- Dashboard shows pending finance records if finance is implemented.
- Dashboard links to detail pages.
- Dashboard handles empty data sources without crashing.
- Dashboard is operational support, not surveillance.

H. Regression checks
- Existing Applications page still works.
- Existing Evaluator surface still works and still uses assignment ownership.
- Existing Student visibility rules remain intact.
- Existing Mentor routes remain intact.
- Existing Student routes remain intact.
- Existing Project/Artifact/Feedback pages remain intact.
- Existing role switching remains intact.
- Existing phone masking / contact visibility rules remain intact if implemented.
- Existing activation token latest-wins behavior remains intact if implemented.
