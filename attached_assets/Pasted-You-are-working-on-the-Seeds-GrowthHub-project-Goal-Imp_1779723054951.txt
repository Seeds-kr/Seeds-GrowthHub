Task:
Implement a lightweight document system for internal GrowthHub operations.

Scope:
1. Documents
- Create document
- Edit document
- Markdown editor
- Markdown preview
- Document detail page
- Document list page
- Visibility setting
- Linked object fields where feasible

2. Templates
- Mark document as template
- List templates
- Clone template into a new document
- Template types: meeting note, event checklist, recruitment checklist, finance template, onboarding document

3. Versions
- Create a version record when document content changes
- Show version history
- Allow viewing previous versions if feasible

4. Checklists
- Support checklist-style Markdown
- Allow documents to be used as event/session checklists later

Implementation constraints:
- Markdown is the source of truth for internal operational documents.
- Do not implement a DOCX editor.
- External DOCX/PDF files can be handled later as attachments or links.
- Do not replace Google Drive/Notion. GrowthHub stores internal docs and metadata.

Acceptance Criteria:

- Admin can edit and preview Markdown.
- Admin can mark a document as template.
- Admin can clone a template into a new document.
- Document versions are created when content changes.
- Document can be linked to a related object if supported.
- Document visibility can be set.

- Internal documents are not visible to students.
- Visibility rules are enforced.
- Unauthorized users receive a clear message.

- Document version history is preserved.
- Cloned document retains template content but becomes a separate document.
- Deleting or archiving a document does not break linked objects.

UX / Error:
- Empty state exists for documents and templates.
- Editor save errors do not lose content.
- Markdown preview is readable.

Regression:

- Existing Sessions, Assignments, Projects, Artifacts, Feedback pages still work.
